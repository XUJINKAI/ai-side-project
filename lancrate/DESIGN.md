# LanCrate 设计文档

> 项目名：LanCrate（中文名：局域箱）  
> 命令名：`lancrate`  
> 文档状态：草案  
> 目标版本：v0.1.0

## 1. 背景

现有项目是一个基于 Mongoose 的最小 C 静态文件服务器，只支持从启动目录下载文件。实际使用场景已经扩展到 Windows 电脑、手机和多台 Linux 虚拟机之间传输文件及文本，因此需要将项目重新设计为一个轻量的局域网临时中转站。

LanCrate 不依赖云服务，也不要求客户端安装应用。服务端启动一个进程，其他设备使用浏览器或 `curl` 即可访问。

## 2. 目标与非目标

### 2.1 产品目标

- 单个可执行文件分发，不要求目标机器安装运行时。
- 支持 Windows 和 Linux，首批覆盖 amd64、arm64。
- 支持浏览器上传、下载和管理文件。
- 支持命令行工具上传、下载和交换文本。
- 提供一块跨设备共享的文本区，用于复制和粘贴短文本。
- 在可信局域网内保持简单，同时具备合理的默认安全边界。
- 能处理大文件，上传过程不将整个文件载入内存。
- 配置少、启动快、停止后不留下后台服务。

### 2.2 非目标

v0.1.0 不包含：

- 公网文件分享和云存储。
- 用户注册、多用户空间和复杂权限模型。
- 文件同步、增量同步和冲突合并。
- 端到端加密。
- 内网穿透和 NAT 穿透。
- 操作系统原生剪贴板同步。
- 桌面 GUI 或系统托盘。
- 服务端在线编辑文件。

## 3. 命名

LanCrate 由 LAN 和 Crate 组成，含义是“局域网里的中转箱”。Crate 可以同时容纳文件和文本，不会把产品限定为单向投递工具。

- 项目名：LanCrate
- 可执行文件：Windows 为 `lancrate.exe`，Linux 为 `lancrate`
- 默认数据目录：当前目录下的 `lancrate-data/`
- 环境变量前缀：`LANCRATE_`

名称在正式公开发布前仍应进行 GitHub、软件包仓库、域名和商标的完整冲突检查。

## 4. 使用场景

### 4.1 电脑向手机发送文件

1. 电脑运行 `lancrate`。
2. 终端显示局域网访问地址和访问码。
3. 手机浏览器打开地址并完成验证。
4. 手机从文件列表中下载文件。

### 4.2 手机向电脑上传文件

1. 手机打开 LanCrate 页面。
2. 选择或拖入文件。
3. 页面显示逐文件上传进度和最终结果。
4. 文件写入电脑上的数据目录。

### 4.3 电脑与虚拟机交换命令或配置

1. 一端将文本保存到共享文本区。
2. 另一端刷新页面或调用 API 获取文本。
3. 使用复制按钮或终端输出完成粘贴。

### 4.4 无桌面环境的 Linux 虚拟机

虚拟机使用 `curl` 和令牌直接调用 HTTP API，不依赖浏览器。

## 5. 技术选型

### 5.1 服务端

使用 Go，仅依赖标准库：

- `net/http`：HTTP 服务、路由、上传和下载。
- `embed`：将 HTML、CSS 和 JavaScript 嵌入可执行文件。
- `crypto/rand`：生成访问令牌。
- `os`、`io`、`path/filepath`：安全地处理文件和流。
- `encoding/json`：API 数据和可选的文本持久化。
- `os/signal`、`context`：优雅关闭。

构建时设置 `CGO_ENABLED=0`，减少目标系统依赖并简化交叉编译。

### 5.2 Web 前端

采用原生 HTML、CSS 和 JavaScript，不使用 Node.js 构建链和前端框架。页面资源通过 `go:embed` 编译进程序。

前端需要支持现代手机及桌面浏览器，并提供基础的响应式布局和无障碍标签。

### 5.3 状态存储

- 文件：直接存储在数据目录的 `files/` 子目录。
- 上传临时文件：存储在同一文件系统的 `.uploading/` 子目录，完成后原子重命名。
- 共享文本：默认只保存在内存中。
- 可选持久化：启用 `--persist-text` 后写入 `state/text.json`。
- v0.1.0 不引入数据库。

## 6. 总体架构

```text
 Browser / curl
       |
       | HTTP
       v
+-------------------------+
|       LanCrate          |
|                         |
|  Auth middleware        |
|       |                 |
|  HTTP API + embedded UI |
|       |          |      |
|  File service  Text hub |
+-------|----------|------+
        |          |
        v          v
   data/files/   memory or
                 text.json
```

所有外部输入都先经过请求大小限制、身份验证和参数校验。文件服务只能访问配置的数据目录，不能把任意 URL 路径直接拼接为系统路径。

## 7. 功能设计

### 7.1 文件列表

页面展示：

- 文件名。
- 文件大小。
- 修改时间。
- 下载入口。
- 在允许时显示删除操作。

v0.1.0 只展示数据目录第一层的普通文件，不展示目录、符号链接和内部状态文件。默认按修改时间倒序排列。

### 7.2 文件上传

- 支持一次选择多个文件。
- 每个文件作为独立请求上传，方便显示进度和失败重试。
- 服务端流式写入临时文件。
- 成功写完并同步关闭后，原子移动至 `files/`。
- 同名文件默认保留两者，例如 `report (1).pdf`。
- 不允许空文件名、路径分隔符、`.`、`..`、控制字符和平台保留名称。
- 超过单文件或总存储上限时，在写满磁盘前拒绝请求。
- 上传失败时删除对应临时文件。

服务端不信任浏览器提供的 MIME 类型。下载响应使用安全的文件名编码，并默认设置 `Content-Disposition: attachment`。

### 7.3 文件下载

- 支持 GET 和 HEAD。
- 支持范围请求，便于大文件续传和媒体播放。
- 下载目标必须是 `files/` 下的普通文件。
- 不跟随符号链接访问数据目录之外的内容。
- 文件不存在时返回统一 JSON 或 HTML 404，不泄露系统绝对路径。

### 7.4 删除文件

- 默认启用，但必须通过身份验证。
- 可用 `--no-delete` 完全关闭。
- 删除接口只接受文件的服务端标识，不接受任意系统路径。
- v0.1.0 为直接删除；未来可增加回收站模式。

### 7.5 共享文本

- 保存一份当前文本及其更新时间。
- 默认最大 UTF-8 文本大小为 1 MiB。
- 支持读取、覆盖和清空。
- 同时修改时采用最后写入者生效，并返回新的版本号。
- 页面显示更新时间和字符数。
- 默认不保存历史，进程退出即清空。

浏览器剪贴板 API 在普通局域网 HTTP 页面中可能不可用。复制按钮应优先调用 Clipboard API；失败时选中文本并提示用户手动复制。共享文本功能本身不得依赖剪贴板权限。

### 7.6 页面更新

v0.1.0 使用低频轮询：

- 文件列表每 5 秒刷新一次。
- 文本版本每 2 秒检查一次。
- 页面不可见时降低轮询频率。

暂不引入 WebSocket。后续如有明显的实时性需求，可改用 Server-Sent Events。

## 8. HTTP API

所有 API 路径位于 `/api/v1/` 下。JSON 响应统一包含 `error` 字段；成功时该字段为空或省略。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/status` | 服务状态、能力和限制 |
| `GET` | `/api/v1/files` | 获取文件列表 |
| `POST` | `/api/v1/files` | 上传单个文件 |
| `GET` | `/api/v1/files/{id}` | 下载文件 |
| `HEAD` | `/api/v1/files/{id}` | 获取下载元数据 |
| `DELETE` | `/api/v1/files/{id}` | 删除文件 |
| `GET` | `/api/v1/text` | 获取共享文本 |
| `PUT` | `/api/v1/text` | 覆盖共享文本 |
| `DELETE` | `/api/v1/text` | 清空共享文本 |

### 8.1 文件标识

API 不直接使用未经编码的文件路径。文件列表为每个文件返回不透明的 URL 安全标识；服务端根据标识查询当前数据目录中的记录。v0.1.0 可以使用文件名的 URL 安全编码，但所有解码结果仍必须重新执行文件名校验。

### 8.2 错误格式

```json
{
  "error": {
    "code": "file_too_large",
    "message": "文件超过允许的大小"
  }
}
```

常见状态码：

- `400`：参数、文件名或请求格式无效。
- `401`：未提供或提供了错误的凭据。
- `404`：资源不存在。
- `409`：状态冲突。
- `413`：请求或文件过大。
- `507`：存储空间不足。
- `500`：未预期的服务端错误。

## 9. 身份验证与安全

### 9.1 默认验证方式

局域网监听模式下，程序启动时生成至少 128 位随机令牌。终端显示带令牌的一次性入口地址。浏览器首次访问后：

1. 服务端验证入口令牌。
2. 设置 `HttpOnly`、`SameSite=Strict` 的会话 Cookie。
3. 重定向到不含令牌的首页，避免令牌长期留在地址栏和历史记录中。

命令行客户端使用：

```text
Authorization: Bearer <token>
```

`--no-auth` 必须由用户显式指定，启动日志应显示醒目警告。

### 9.2 网络边界

- 默认监听 `0.0.0.0:8080`，方便手机和虚拟机访问，但强制启用随机令牌。
- `--local` 等价于监听 `127.0.0.1:8080`。
- 允许通过 `--listen IP:PORT` 精确指定网卡。
- 不自动修改 Windows 或 Linux 防火墙。
- 不承诺可安全直接暴露到公网。

如需跨公网使用，应通过 WireGuard、Tailscale、SSH 隧道或受控的反向代理接入，而不是直接进行端口映射。

### 9.3 路径与文件安全

- 使用清洗后的基本文件名，拒绝任何目录成分。
- 数据目录在启动时转换为绝对路径并固定。
- 拒绝符号链接和非普通文件。
- 上传临时文件使用不可预测名称和排他创建。
- 不把绝对路径、令牌和 Cookie 写入访问日志。
- 所有修改接口只接受 POST、PUT 或 DELETE，不使用 GET 改变状态。

### 9.4 HTTP 防护

- 限制请求头大小、请求体大小和并发上传数。
- 配置读取头、读取、写入和空闲超时。
- 设置 `X-Content-Type-Options: nosniff`。
- 设置限制性 CSP，前端资源不依赖外部 CDN。
- 会话 Cookie 开启 `HttpOnly` 和 `SameSite=Strict`；启用 HTTPS 时增加 `Secure`。
- 对浏览器修改请求校验 `Origin`，降低局域网内跨站请求风险。
- 对登录失败进行轻量速率限制。

## 10. CLI 设计

```text
lancrate [options]

  -d, --dir PATH              数据目录，默认 ./lancrate-data
  -l, --listen ADDRESS        监听地址，默认 0.0.0.0:8080
      --local                 只监听 127.0.0.1
  -t, --token TOKEN           指定访问令牌；auto 表示随机生成
      --no-auth               关闭验证并显示安全警告
      --max-file SIZE         单文件上限，默认 2G
      --max-storage SIZE      总存储上限，默认 20G
      --clipboard-limit SIZE  共享文本上限，默认 1M
      --persist-text          持久化共享文本
      --no-delete             禁用文件删除
      --read-only             禁用上传、删除和文本修改
      --version               显示版本
  -h, --help                  显示帮助
```

退出码：

- `0`：正常停止。
- `1`：运行期错误。
- `2`：命令行参数无效。
- `3`：无法初始化数据目录。
- `4`：无法绑定监听地址。

## 11. 启动与关闭

启动流程：

1. 解析并验证参数。
2. 创建或验证数据目录。
3. 清理遗留的过期上传临时文件。
4. 生成或加载访问令牌。
5. 构造 HTTP 服务及超时配置。
6. 枚举可访问的本机局域网地址并输出 URL。
7. 开始监听。

收到 Ctrl+C、SIGINT 或 SIGTERM 后停止接收新请求，给予正在进行的上传短暂宽限期，然后关闭服务并清理临时资源。

## 12. 虚拟机网络说明

LanCrate 只负责监听指定网络接口，不尝试改变虚拟机网络配置。

- NAT：虚拟机通常可以访问宿主机，但具体宿主机地址由虚拟化软件决定。
- 桥接：虚拟机与宿主机处于同一局域网，访问方式最直观。
- Host-only：适合只在宿主机和虚拟机之间传输，手机通常无法访问。
- 容器：通过端口发布访问，例如将容器端口映射到宿主机 8080。

README 应分别给出 Hyper-V、VMware、VirtualBox 和常见容器环境的排查提示，但核心程序不依赖任何一种虚拟化平台。

## 14. 构建与发布

首批发布目标：

```text
out/
├── lancrate-windows-amd64.exe
├── lancrate-windows-arm64.exe
├── lancrate-linux-amd64
└── lancrate-linux-arm64
```

构建要求：

- 使用锁定的 Go 主版本。
- `CGO_ENABLED=0`。
- 注入版本号、Git 提交和构建时间。
- 默认执行 `gofmt`、`go vet` 和 `go test ./...`。
- GitHub Actions 可在打标签时构建压缩包和校验文件。
- 不提交 `out/`、覆盖率文件、临时上传和本地数据目录。

## 15. 测试策略

### 15.1 单元测试

- 参数解析与大小单位解析。
- 文件名清洗和跨平台保留名称。
- 路径穿越、绝对路径和编码绕过。
- 同名文件生成策略。
- 令牌生成与固定时间比较。
- 共享文本大小和版本控制。

### 15.2 HTTP 集成测试

- 未认证请求被拒绝。
- 上传、列表、下载和删除完整流程。
- 大文件使用流式路径，不出现与文件大小相当的内存增长。
- 超限请求返回 413，且不留下临时文件。
- Range、HEAD 和特殊字符文件名。
- 只读模式和禁止删除模式。
- 并发上传同名文件不会互相覆盖。
- Ctrl+C/关闭期间不接受新请求。

### 15.3 平台验证

- Windows 11 amd64。
- Linux amd64。
- Linux arm64。
- Android Chrome 和 iOS Safari 的网页上传、下载及手动复制回退。
- NAT、桥接和 Host-only 虚拟机网络至少各验证一次。

## 16. 可观测性

默认日志面向终端用户，保持简洁：

- 启动地址、数据目录和安全模式。
- 上传完成、下载失败和删除结果。
- 关闭原因。

默认不记录正文、令牌、Cookie、完整查询字符串或共享文本。`--verbose` 可以输出请求方法、路径模板、状态码、耗时和传输字节数。

## 17. v0.1.0 验收标准

- 四个目标平台的产物均可独立启动。
- 手机和虚拟机能通过浏览器完成文件上传与下载。
- Linux 虚拟机能通过 `curl` 上传、下载、读取和写入文本。
- 默认配置不会共享源码目录或任意系统目录。
- 缺少认证的修改请求无法生效。
- 2 GiB 范围内的上传采用流式处理。
- 非法文件名、路径穿越和符号链接测试全部通过。
- Ctrl+C 能在限定时间内优雅退出。
- README 包含构建、运行、防火墙和虚拟机网络说明。

## 18. 后续演进

按需求强度依次考虑：

1. 页面二维码，减少手机输入地址的成本。
2. Server-Sent Events 实时更新文件和文本状态。
3. 文本历史和自动过期。
4. 文件自动过期及存储配额回收。
5. 可选 HTTPS 和反向代理部署说明。
6. 校验和显示及上传后完整性验证。
7. 可选回收站。
8. 系统托盘和开机启动集成。

不建议在核心功能稳定前引入账户系统、数据库、前端框架或公网中继服务。

## 19. 迁移策略

现有 C/Mongoose 实现不直接演进为新服务。迁移时：

1. 保留旧代码到 `legacy-c/`，注明它仅为静态文件服务器示例。
2. 在仓库根目录建立新的 Go 项目结构。
3. 先实现后端 API 和集成测试，再实现 Web UI。
4. 完成跨平台验证后，将 Go 版本设为默认实现。

是否保留 `legacy-c/` 可在实施前决定；删除或移动现有文件前应先确认 Git 归属及用户修改。
