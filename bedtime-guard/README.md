# Bedtime Guard

Windows 常驻睡眠提醒与定时强制休息工具。C# / .NET 10 / WPF；Windows 服务保存计划、执行承诺规则并有限恢复托盘进程。

## 下载与使用

发布内容为一个 **`bedtime-guard-win-x64.exe`，不包含 .NET 运行时**，另附 `bedtime-guard-build.json` 记录构建信息和 SHA-256。安装后的内部文件名仍为 `BedtimeGuard.exe`。Windows 11 x64 需要先安装 [Microsoft .NET 10 Desktop Runtime（桌面运行时）](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)，请选择与 EXE 一致的架构；只装普通 .NET Runtime 不够。未安装时，Windows 的 .NET 启动提示会引导下载。应用不自动安装运行时。

1. 从 [Latest builds](https://github.com/XUJINKAI/ai-side-project/releases/tag/latest-build) 下载 `bedtime-guard-win-x64.exe` 并双击；PR 测试版可从 Actions 的 `release-bedtime-guard` 附件解压获得。
2. 在窗口中选择安装位置，点击 **安装**，确认 Windows 管理员授权。无需 CMD、PowerShell 或安装脚本。
3. 安装完成后在同一窗口配置睡眠计划、定时休息，勾选需要的功能并保存。两项默认都未启用。
4. 安装后从开始菜单或托盘打开设置。关闭设置窗口继续后台运行。

程序默认安装到 `C:\Program Files\BedtimeGuard`，也可以选择 Program Files 下的直属新文件夹。安装后的程序仍只有一个 EXE；状态位于受保护的 `C:\ProgramData\BedtimeGuard`。服务开机启动，在指定用户登录后启动托盘。单个 EXE 同时提供界面、服务和独立策略恢复入口。

## 睡眠计划

| 阶段 | 默认时间 | 行为 |
| --- | --- | --- |
| 可调整 | 承诺开始之前 | 修改或停用计划 |
| 随机承诺 | 20:00 ± 30 分钟 | 每晚抽取一次，静默冻结当晚安排 |
| 首次提醒 | 22:00 | 弹窗提醒，此时不能取消或延期 |
| 收尾提醒 | 22:55、22:59 | 再次提醒；最后一分钟各显示器倒计时 |
| 限制 | 23:00—次日 06:00 | Windows 原生锁屏，解锁后再次锁定 |
| 解除 | 次日 06:00 | 停止限制，恢复本工具临时修改的策略 |

具体随机承诺时间不提前公布，重复保存或重启不会重新抽签。整个随机范围必须严格早于首次提醒。承诺后仍可保存后续计划，但已经冻结的当晚不能取消或延期。星期归属开始承诺的晚上，周五计划包括周六凌晨。

## 定时强制休息

与睡眠计划独立启用，四项均使用整数分钟；睡眠计划也只接受整分钟时间。四项均可在窗口配置：

| 配置 | 默认值 | 范围/含义 |
| --- | --- | --- |
| 工作间隔 a | 60 分钟 | 11—1440 分钟，必须是整数 |
| 休息时长 b | 10 分钟 | 1—180 分钟 |
| 提前提醒 c | 10 分钟 | 距离休息开始的提前量，可为 0 |
| 提前承诺 d | 10 分钟 | d ≥ c，且 a − d ≥ 11；可为 0 |

每轮非承诺工作时间必须严格大于 10 分钟，因此要求 **a − d ≥ 11**。例如 a=3、b=5 会被拒绝；a=11、b=15、c=0、d=0 则有效：工作 11 分钟、休息 15 分钟，休息结束才开始下一轮，不会在休息中叠加触发。测试有提前提醒的最短示例可用 a=13、b=1、c=1、d=2。

默认累计工作 **50 分钟**时提醒并进入承诺期，**60 分钟**开始锁屏休息 **10 分钟**，结束后重新累计下一轮。也可将 d 设为 20、c 设为 10：40 分钟时先承诺，50 分钟才提醒。

- 承诺前只累计目标账号处于已解锁交互会话且服务正常运行的时间；锁屏、注销、睡眠、关机不累计。不会检测键鼠活动，因此解锁后离开座位仍算使用时间。
- 进入承诺期时固定本轮提醒、锁屏、解除时间和策略选项。此后按实际时间推进，手动锁屏或睡眠不会推迟本轮，修改配置只影响后续轮次。
- 若在睡眠/关机期间整轮休息已结束，恢复后重新累计，不补锁屏。
- 承诺前修改间隔保留已累计时间；停用会清零。承诺后的停用等本轮结束生效。
- 进度每 15 秒保存一次，正常服务停止会保存；突然崩溃最多丢失约 15 秒未承诺进度。承诺快照立即保存，重启不会重置本轮。
- 夜间限制优先，进入夜间限制时清零定时休息；夜间解除后重新累计。如果两个提醒重叠，优先展示距离锁屏更近的一项。

## 卸载与紧急管理

主窗口仅提供 **安装、重新启用、卸载** 管理按钮。任一睡眠或休息安排进入承诺期后，直到该安排解除，卸载按钮变灰；提醒期、限制期也不能卸载。无法连接后台确认状态时，界面暂不开放卸载。Windows“已安装的应用”的卸载入口同样受后台校验约束。

没有图形暂停按钮、开始菜单恢复快捷方式或 `--recovery` 短参数。管理员紧急暂停或强制卸载需要手动运行下面的完整参数（PowerShell 示例；这些命令仅用于紧急管理，正常安装和使用仍通过 UI）：

```powershell
# 紧急暂停：保留计划，直到手动点击“重新启用”
& 'C:\Program Files\BedtimeGuard\BedtimeGuard.exe' --i-confirm-i-am-breaking-my-commitment-and-want-to-emergency-pause-bedtime-guard-until-i-manually-enable-it-again

# 强制卸载：解除限制并删除程序及所有计划数据
& 'C:\Program Files\BedtimeGuard\BedtimeGuard.exe' --i-confirm-i-am-breaking-my-commitment-and-want-to-permanently-uninstall-bedtime-guard-and-delete-all-my-saved-plans
```

自定义安装目录请替换 EXE 路径，也可以使用下载的同版本 EXE。命令会请求管理员授权并显示操作确认；长参数用于增加主动绕过的成本，不是密码。紧急暂停后重新启用时，尚未结束的承诺继续执行。普通卸载只在没有有效承诺时允许；强制卸载仍先恢复策略，再移除程序、服务、任务、快捷方式和数据。维护通过临时 EXE 副本完成，必要时在重启时清理临时文件。

若受约束账号的注册表尚未加载，恢复会明确报错并保留恢复记录；让该账号登录后再次运行紧急暂停命令。恢复未完成时卸载会中止。检测到已有安装或数据时会询问是否覆盖安装。确认后更新程序、修复服务和卸载登记，保留配置、累计进度、已承诺安排、受约束账号及暂停状态；有效承诺不会因覆盖而清空。覆盖前备份状态为 `state.before-install.json`。仅剩有效数据、没有服务或安装记录也可修复；损坏状态不会擅自重置。已有安装需选择原安装目录。配置损坏时服务拒绝启动，不静默重置承诺；可先运行紧急暂停命令再排查或强制卸载重装。

下载新版后直接双击下载的 EXE，点击安装并确认覆盖即可升级；不会转去旧版托盘界面。工作间隔现统一使用分钟，默认 60；旧版小时配置会自动换算，1 小时仍为 60 分钟。旧版小数分钟向上取整；非承诺期不足 11 分钟的旧配置会延长后续工作间隔，已承诺的固定安排不变。极限提前量会限制在 1429 分钟，以保留 11 分钟非承诺期。

## 约束边界

- 可选“承诺期开始后临时禁用任务管理器”同时适用于睡眠和休息，默认关闭。只针对指定账号，保留原始值，不接管已有的限制；检测到域/MDM 管理时拒绝修改。建议个人未受管理的 Windows 专业版，家庭版策略效果需实机确认。
- 界面被结束后，后台服务每 5 秒检查恢复；同一会话 5 分钟内最多启动 3 次。服务异常退出最多由 Windows 自动重启两次。
- 不修改密码、不注销、不关闭其他应用；未保存文件仍保留，下载/编译等后台任务可能继续。输入密码解锁后会再次锁定，存在短暂操作间隙。
- 不使用驱动、注入、进程隐藏，不拦截 Ctrl+Alt+Del，不阻止管理员恢复/卸载。不防管理员主动改系统时钟、安全模式或系统文件替换。
- 独立恢复任务在开机、登录和每分钟检查策略记录，到期或服务心跳失联超过 2 分钟时尝试还原。系统调度和用户注册表加载可能导致延迟。服务失联时界面停止使用过期状态锁屏。

## 开发与验证

开发需要 .NET 10 SDK；以下命令仅供开发，不是用户安装步骤。

```powershell
dotnet run --project tests/BedtimeGuard.Tests -c Release
dotnet run --project tests/BedtimeGuard.Windows.Tests -c Release
./build.ps1
# 可交叉构建 ARM64，但自动桌面/安装测试当前仅覆盖 x64
./build.ps1 -Runtime win-arm64
```

`build.ps1` 运行核心和 Windows 策略测试，再发布不带运行时的单 EXE，输出 `out/BedtimeGuard-win-x64/BedtimeGuard.exe`。GitHub Actions 在一次性 Windows runner 验证实际窗口启动、原生安装、真实服务/IPC、承诺冻结、恢复、重新启用、卸载；产物附 JSON 构建信息及 SHA-256。开发者集成测试只能在可丢弃的管理员测试机器运行。

自动测试不能替代实际桌面的 UAC 点击、锁屏/解锁、多屏缩放和休眠唤醒验收，见 [验收清单](docs/ACCEPTANCE.md)。

## 结构

- `src/BedtimeGuard.Core`：睡眠与休息状态机、校验、冻结与持久化。
- `src/BedtimeGuard.Windows`：受保护路径、策略恢复事务、会话检测/启动和 IPC。
- `src/BedtimeGuard.Service`：权威后台服务、原生安装/卸载和独立恢复任务。
- `src/BedtimeGuard.App`：单 EXE 入口、WPF 管理/设置、托盘、提醒和锁屏。
- `tests`：核心时间规则、隔离注册表事务、Windows 安装闭环。

见 [设计说明](docs/DESIGN.md)。
